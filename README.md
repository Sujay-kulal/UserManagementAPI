# User Management API

A beginner-friendly RESTful API built with ASP.NET Core and C# for managing users. This project was developed as part of a Coursera backend development assignment.

## Features
- **CRUD Operations**: Create, Read, Update, and Delete users.
- **In-Memory Storage**: Uses an in-memory collection to store users without needing a complex database setup.
- **Data Validation**: Uses ASP.NET Core `DataAnnotations` to ensure data integrity.
- **Custom Middleware**: Includes a custom logging middleware to track HTTP requests and responses.
- **Swagger/OpenAPI**: Built-in support for testing endpoints easily.

## Setup Instructions

1. Ensure you have the .NET SDK installed.
2. Navigate to the project directory:
   ```bash
   cd UserManagementAPI
   ```
3. Build the project:
   ```bash
   dotnet build
   ```
4. Run the API:
   ```bash
   dotnet run
   ```
5. Open your browser and navigate to `http://localhost:5280` to view the Swagger UI and interact with the endpoints.

## API Endpoints

- `GET /api/users` - Retrieves all users (Returns 200 OK).
- `GET /api/users/{id}` - Retrieves a specific user by ID (Returns 200 OK or 404 Not Found).
- `POST /api/users` - Creates a new user (Returns 201 Created or 400 Bad Request for validation errors).
- `PUT /api/users/{id}` - Updates an existing user (Returns 200 OK, 400 Bad Request, or 404 Not Found).
- `DELETE /api/users/{id}` - Deletes a user (Returns 204 No Content or 404 Not Found).

## Validation

The `User` model enforces the following rules:
- **Id**: Auto-generated by the server.
- **Name**: Required field. Must be between 1 and 100 characters.
- **Email**: Required field. Must conform to a valid email format.

Invalid inputs will automatically trigger a `400 Bad Request` response.

## Middleware

A custom `LoggingMiddleware` is implemented to log the details of every HTTP request:
- Logs the incoming HTTP Method and Request Path.
- Passes the request to the next middleware in the pipeline.
- Logs the outgoing HTTP Response Status Code.

## Debugging & AI Assistance

During development, **GitHub Copilot / AI Assistance** was utilized to help write boilerplate code, scaffold the project, and identify and resolve common bugs. Specific fixes identified and implemented include:
- **HTTP Status Codes**: Ensuring correct RESTful codes were returned (e.g., `201 Created` for POST, `204 No Content` for DELETE, and `404 Not Found` for missing resources instead of generic responses or null reference exceptions).
- **Validation**: Enforcing explicit checks and gracefully handling empty request bodies.
- **Data Integrity**: Preventing duplicate email registrations and ensuring the URL ID matches the body ID on PUT requests to avoid unintentional overwrites.
- **Thread Safety**: Implementing `Interlocked.Increment` for safe ID generation in the static in-memory list.
- **Proper Middleware Chaining**: Ensuring `await _next(context)` is called in the middleware so requests do not hang.
